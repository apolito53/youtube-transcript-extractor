# YouTube Transcript Extractor

A small local web app that turns a YouTube URL into clean, copyable Markdown.
It fetches the video's available captions, removes caption-window repetition,
groups the text into paragraphs, and can optionally format the result with the
OpenAI Responses API.

## Quick start

This project supports Python 3.8 or newer. Python 3.11+ is recommended for a
fresh environment.

Create an environment and install the project:

    python3 -m venv .venv
    .venv/bin/python -m pip install -e ".[dev]"

Copy .env.example to .env. AI formatting is optional; extraction and clean
Markdown work without an OpenAI key. To enable formatting, set:

    OPENAI_API_KEY=your-key
    OPENAI_MODEL=gpt-5.6-luna

Start the app:

    ./start.sh

Open http://127.0.0.1:8765.

The script uses the local virtualenv and forwards environment settings such as
YTX_PORT. For example:

    YTX_PORT=8765 ./start.sh

If uv is installed, the equivalent commands are:

    uv sync --extra dev
    uv run ytx

## What V1 does

- Accepts standard YouTube watch, short, Shorts, live, embed, and /v/ URLs.
- Prefers manual English captions, then autogenerated English captions.
- Allows a language code such as es or ja.
- Preserves non-speech cues such as [Music].
- Optionally adds timestamp links back to the video.
- Provides deterministic clean output even when AI formatting is unavailable.
- Keeps transcript data in the current browser session; there is no database.

## Configuration

The application reads these environment variables:

- OPENAI_API_KEY: optional key for AI formatting.
- OPENAI_MODEL: model name, default gpt-5.6-luna.
- YTX_HOST: bind address, default 127.0.0.1.
- YTX_PORT: bind port, default 8000.
- YTX_MAX_TRANSCRIPT_CHARS: maximum transcript size sent to the formatter,
  default 500000.

The YouTube caption adapter uses youtube-transcript-api, which accesses an
undocumented YouTube web-client endpoint. It is intentionally isolated in
youtube.py so a future fallback can be added without changing the rest of
the app.

## Deployment note

The app starts successfully on Vercel, but YouTube may block transcript
requests from Vercel's serverless/cloud-provider IPs. This is an egress issue,
not a FastAPI or OpenAI configuration issue. Before relying on a public
deployment, add a rotating residential proxy supported by
`youtube-transcript-api`, or move transcript extraction behind a hosted
transcript provider. Do not commit proxy credentials; keep them in deployment
environment variables.

## Development

Run the focused test suite:

    .venv/bin/pytest

The live YouTube smoke test is intentionally not part of the default suite;
caption availability and IP blocking are external state. Use the browser
workflow with a public captioned video when you want an end-to-end check.
